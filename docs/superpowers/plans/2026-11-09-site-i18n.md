# Site em três idiomas (pt, en, es) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O site `apps/site` passa a existir em português (padrão), inglês e espanhol, com um dropdown de idioma no menu, uma URL estática por idioma e um idioma só publicado quando aprovado.

**Architecture:** O conteúdo sai de um `COPY` global e vira dados por idioma (`src/content/copy/{pt,en,es}.ts`, `src/content/legal/{pt,en,es}.ts`). As páginas (servidor) recebem o idioma da rota; componentes de cliente leem de um `LocaleProvider`. Rotas: português em um grupo de rotas `(pt)` (URL `/`) e inglês/espanhol em `[lang]`, cada grupo com seu layout raiz (`<html lang>` correto). Tamanhos dos títulos 3D e a largura do CSS do hero passam a ser por idioma.

**Tech Stack:** Next 16.4.5 (export estático), React 19, TypeScript, Vitest + Testing Library (jsdom), Playwright, opentype.js (medição dos títulos).

**Spec:** `docs/superpowers/specs/2026-11-09-site-i18n-design.md` (aprovada pelo João Victor).

## Global Constraints

- Branch de trabalho: `feat/site-i18n`. Nunca escrever na `main`; o João Victor decide o merge.
- Comandos rodam em `apps/site` (`cd /Users/mac/dev/dynamolabs/apps/site`). Testes unitários: `pnpm vitest run <arquivo>`; e2e: `pnpm exec playwright test <arquivo>`; tipos: `pnpm typecheck`.
- Next 16 não é o Next conhecido: antes de mexer em rotas, layouts, metadata ou sitemap, ler o guia correspondente em `node_modules/next/dist/docs/` (ver `apps/site/AGENTS.md`).
- Idiomas: `pt` (padrão, em `/`), `en` (`/en`), `es` (`/es`). Caminhos legais: pt `/privacidade` `/termos`; en `/en/privacy` `/en/terms`; es `/es/privacidad` `/es/terminos`.
- `<html lang>`: `pt-BR`, `en`, `es`. Open Graph locale: `pt_BR`, `en_US`, `es_ES`.
- Idioma publicado = `copy.status === "final"` e `legal.status === "final"`. Idioma provisório existe só em `next dev` e em builds com `NEXT_PUBLIC_E2E=1`. Português sempre publicável; `check:release` só avisa sobre idiomas de fora, não falha por eles.
- Estado final desta branch: `pt` com os dois status "final"; `en` e `es` com os dois "provisional" (o João Victor aprova depois).
- Sem cookie, sem localStorage, sem detecção do idioma do navegador. O payload do formulário e o CRM não mudam.
- Tom: inglês americano; espanhol latino-americano neutro, tratando por "tú". Nomes (Dynamo, Dynamo Labs, WhatsApp) não mudam. Textos legais = tradução fiel do português aprovado, sem cláusula nova.
- Títulos em en/es: mesmo número de linhas que o português (hero 2, s2 3, video2 3) e linha mais larga no máximo 15% acima da do português; a `keyword` é uma palavra do próprio título.
